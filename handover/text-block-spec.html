Text Block

A flexible text/media block for article and inspiration templates. One shared markup shape — eyebrow, heading, rich body copy, optional CTA link, optional media — with eight layout configurations (text-only, image top/bottom/left/right, video left/right/full-width) controlled entirely by a root modifier class.

Overview

Text Block

Anatomy & Rules

Two top-level children: .ufs-text-block__content (eyebrow, heading, body, link) and, on every variant except the base text-only one, .ufs-text-block__media (an image or a .ufs-video-embed). Only the heading is required — eyebrow, extra paragraphs, the link and the media block are all optional, each a plain sibling that can be omitted with no other markup changes.

ℹ️
The container is deliberately not the 96px-desktop / 16px-mobile outer gutter that .ufs-title-section and .ufs-teaser-lg use elsewhere in this handover. Text Block is an article-body component, not a marketing section — its own container is just max-width: 960px; margin: 0 auto; padding: 0 var(--space-4) (16px), full width below that. Don't "fix" this to match the other section components without knowing this was intentional.
💡
The heading's semantic tag and its visual size are independent, same pattern as .ufs-title-section__heading. .ufs-text-block__heading alone renders at the smaller (30px/h3) size; add --lead for the larger (40px/h2) size. Which HTML tag (<h2>/<h3>/<h4>) to use is the page author's own document-outline decision — as a starting default, an intro-style opening block (eyebrow + --lead) reads well as an <h2>, and the smaller recurring body blocks further down a page read well as <h3>, but the CSS never enforces either.
💡
DOM order inside .ufs-text-block is always (.ufs-text-block__content, .ufs-text-block__media) — on every one of the eight configurations below, media always comes second in the markup. Every visual reordering (image-top's swap above the text, image-left's flip to the other side, mobile's media-first stacking on the split variants) is done purely in CSS via order or flex-direction, never by moving markup around.

Internationalisation

i18n & RTL

Every layout in this component is plain flex with no literal left/right or text-align: left anywhere — row/row-reverse both auto-mirror under dir="rtl", the same way .ufs-teaser-lg's --image-left modifier does. No [dir="rtl"] overrides exist in this component's CSS.

💡
Nothing in this component's CSS is RTL-specific — column order, alignment and the CTA link's underline all mirror for free. If a future variant ever needs a physical left/right value, that's the point an explicit [dir="rtl"] override becomes necessary — see Promo Banner's spec for a worked example of that case.

Usage

No JS required for the text/image variants. The video variants (--video-left, --video-right, --video-full) reuse .ufs-video-embed as-is — if it's already on the page (e.g. from a Flex Carousel or Training Hero), no new CSS/JS is needed for text-block's video slot beyond the small fluid-width override below; otherwise pull in .ufs-video-embed's own CSS, the shared .lb-overlay lightbox markup and its click-listener script from video-embed-spec.html unchanged.

<div class="ufs-text-block ufs-text-block--image-right">  <!-- swap to --image-left / --image-top / --image-bottom / --video-left / --video-right / --video-full, or drop the modifier entirely for text-only -->
