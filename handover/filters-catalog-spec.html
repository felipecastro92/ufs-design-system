Filters & Catalog Toolbar

The search + filter system that sits above a catalog grid: a sticky filters bar (search, quick dropdowns, "All filters"), a popular-filters pill shortcut row, the full-filter side drawer, and the results-count/sort toolbar.

Source

Overview

Full Component Preview

Five pieces, all wired to one shared filterState object on the live page (search input excluded — it's cosmetic here, no live filtering wired): the Filters Bar (search + 3 quick dropdowns + "All filters"), Popular Filters pills, the All Filters side drawer, and the Catalog Toolbar (results count + sort). This spec documents each as static, labelled states rather than porting the live filtering engine — see the note in Filter Dropdown below.

Structure

Filters Bar

.ufs-filters-bar is a sticky row (position: sticky; top: var(--nav-h)) that parks directly under the header once scrolled past: a search input (__search, cosmetic — no live filtering wired), up to any number of quick-filter dropdowns (.ufs-filters-dropdown, desktop-only — see Responsive below), and an "All filters" button (.ufs-filters-allbtn, a .btn.btn-secondary that opens the full drawer). Background is mushroom-100 with rounded corners at rest; scrolled under the header the top corners square off via .is-stuck (JS-toggled, see Sticky & Responsive Behaviour).

Filter Dropdown

Each quick dropdown (.ufs-filters-dropdown) opens a popover (__panel) with a checkbox list for that category (reuses .fi-checkbox — see index.html) and a Clear/Save footer (__ft). Selections here stage in a draft state and only commit to the shared filter state on Save — closing without saving discards the draft. This differs from the All Filters drawer below, where each checkbox commits live. A count badge (.ufs-filters-badge) appears on the trigger once that category has active (saved) filters.

⚠️
The live page wires this with toggleFilterDropdown(), a per-category draft object (quickFilterDraft), and a shared filterState synced across the dropdowns, popular-filter pills, and drawer (syncFilterUI()). This spec shows each resulting visual state as a static, labelled specimen rather than the working engine — see template-catalog.html for the live logic.

Popular Filters

A shortcut row of pill toggles (.ufs-popular-filters) for a handful of commonly-used filter values, sitting directly below the Filters Bar. Each pill reads/writes the same shared filter state as the quick dropdowns and the drawer accordion — activating a pill checks the matching checkbox in both other surfaces, and vice versa. data-filter-key / data-filter-value on each pill map it back to its category and option.

Structure

All Filters Drawer

Opened by the Filters Bar's "All filters" button (and the only path to filters on mobile/tablet, since the quick dropdowns hide below 1280px — see Responsive). It reuses the shared .signin-panel right-side drawer scaffold — see nav-header-spec.html for that base anatomy — with drawer-specific content: a multi-open accordion (.ufs-filters-accordion, one item per filter category) containing checkbox lists (.ufs-filters-checklist, orange-accent checked state), and an always-visible sticky footer with Clear filters / Show Results buttons.

💡
Unlike the quick dropdowns' draft-then-Save pattern, checkboxes here commit to the shared filter state live — each toggle immediately updates the results count, the drawer's own footer button labels/disabled state, and syncs the quick-dropdown badges and popular-filter pills.
Real case scenario — on-screen position & scale
The full .signin-panel scaffold, all 6 filter categories (only the first open by default, matching the live page), pinned to the right edge at full viewport height above a dimmed backdrop — the drawer's actual on-screen footprint, not an isolated fragment. The page mock behind it is a simplified stand-in only; the real Filters Bar / Catalog Toolbar it sits above are documented in full further up this page.

Catalog Toolbar

A row (.ufs-catalog-toolbar) holding the results count on the left (.ufs-catalog-results, e.g. "343 recipes") and a sort control on the right (.ufs-catalog-sort) — a plain text+chevron trigger (no button box) that opens a small options panel of radio choices. Selecting an option just updates the trigger's label; it doesn't re-order the grid in this prototype. Unlike the filters dropdowns, this stays a row at every breakpoint, including mobile, rather than collapsing.

Responsive

Sticky & Responsive Behaviour

The Filters Bar is position: sticky against the page's own scroll, so its "stuck" and mobile-docked states can't be reproduced live inside a spec-doc card — this section documents them as annotated states instead. See template-catalog.html for the working syncFiltersBarStuck() / hideMobileSearchBar() / showMobileSearchBar() logic.

Breakpoints
≥ 1480pxmax-width: 1440pxFilters Bar, Popular Filters & Catalog Toolbar cap wider than the 1280px default
1280–1479pxdefault, 1280px capall 3 quick dropdowns visible
≤ 1279px.ufs-filters-dropdown { display: none }quick dropdowns hide — "All filters" drawer becomes the only path to filtering
≤ 1024pxtop: var(--mnav-h) + var(--msearch-bar-h)sticky offset follows the mobile nav + mobile search bar instead of the desktop nav
≤ 768px.ufs-filters-allbtn__label { display: none }"All filters" becomes icon-only, width var(--space-12)
is-stuck

CSS has no selector for "currently stuck" under position: sticky, so syncFiltersBarStuck() compares the bar's live getBoundingClientRect().top against its own computed sticky offset on scroll, toggling .is-stuck — which squares off the top corners so the bar reads as flush with the header above it.

Mobile: docking with the search bar

Below 1024px, the Filters Bar and the persistent mobile search bar (see nav-header-spec.html) trade off the same slot on scroll: both start visible, stacked, on initial load. Scrolling down hides the search bar and adds .is-docked to the Filters Bar, moving its sticky offset up to sit flush under the mobile nav in the search bar's place. Scrolling back up brings the search bar back and adds .is-hidden to the Filters Bar (gated on also having .is-stuck, so it can't apply while the bar is still in its normal flow position), translating it out of view instead.

Internationalisation

i18n & RTL

The Filters Bar, dropdowns, and Popular Filters are all flex rows built with logical/direction-agnostic properties (gap, no physical margin-left/right), so dir="rtl" mirrors them with no overrides needed beyond what .fi-checkbox, .btn, and .signin-panel already handle at the base level (see their respective specs).
