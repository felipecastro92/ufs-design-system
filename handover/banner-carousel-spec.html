Banner Carousel

A Flex Carousel variant: a fixed intro panel (logo, title, description, primary CTA) beside — or, on mobile, above — the same scrollable tile carousel, pagination and arrow controls as Flex Carousel. Structure, card content and the 4 colour variants, documented for implementation.

Source
New — Figma only
Format·HTML + CSS + JS
Overview

Full Component Preview

A single <section class="ufs-banner-carousel"> — two top-level children: __panel (logo, title, description, primary CTA) and __carousel, which wraps the exact same .ufs-carousel-track/__spacer/__card/-dots/-arrow engine documented in Flex Carousel, initialised by the same initFlexCarousel() function. The panel sits beside the carousel on desktop and stacks above it on mobile — pagination, swipe and the no-scroll ("compact") state all behave identically to Flex Carousel because it is Flex Carousel's engine, reused rather than reimplemented. The one difference is purely visual, not behavioural: when compact, Banner Carousel also groups __panel and __carousel together and centres them as one unit, rather than just centring the cards within an already-full-width carousel column — see Pagination & Arrows.

Structure

Anatomy

__panel is a fixed-width (378px) column: an optional __logo, an __intro wrapping __title/__desc, then a required primary CTA. __carousel is a flexible column that fills the remaining width: __track-wrap (the same bleed-and-clip wrapper Flex Carousel uses, but trailing-edge only — see the notice below) around .ufs-carousel-track, then __foot holding .ufs-carousel-dots and __arrows.

⚠️
Flex Carousel bleeds its track to the true viewport edge on both sides, because the whole component spans full width. Banner Carousel's __carousel column only touches the viewport edge on its trailing side (__panel occupies the leading side) — so on desktop, only __track-wrap's trailing margin is negative and the leading .ufs-carousel-spacer stays at zero width. Both come back on mobile, once __panel stacks above and __carousel reclaims the full bled width itself — see Desktop vs. Mobile.

Structure

Card Content

Unlike Flex Carousel — whose card is still a deliberately empty placeholder — Banner Carousel ships with real content: a Recipe Tile (.ufs-tile, no eyebrow, no CTA — the whole tile is the click target), reused verbatim from tiles-spec.html, no new CSS. The carousel engine treats the card slot the same way either component: .ufs-carousel-card provides spacing and flex behaviour, and whatever sits inside it is content — any .ufs-tile type can be dropped in, exactly the same "different tile types, same engine" flexibility Flex Carousel already has. See Colour Variants below for three other types (Product, Training, Article) in the same slot.

The 2-class technique
Already established in tiles-spec.html for Chef Tile inside Flex Carousel — reused here unchanged.
CSS
/* .ufs-carousel-card alone would apply its own generic width/height/
   background/border-radius (see Flex Carousel), which .ufs-tile's own
   rules — same specificity, later in source order — naturally override
   for background/border/radius. Width/height still need an explicit
   compound-selector override, since those are set at equal specificity
   by BOTH .ufs-carousel-card and .ufs-tile individually. */
.ufs-carousel-card.ufs-tile { width: 320px; min-width: 320px; height: auto; }

ℹ️
The Figma reference's desktop tile is 353px wide (320px on mobile). This spec fixes it at 320px on every breakpoint instead — same simplification tiles-spec.html already made for Chef Tile in a carousel ("width fixed at every viewport, same rule as the other carousel tiles"), for the same reason: one width value to maintain, and .ufs-tile's own min-width:320px already lands there with zero extra CSS.
⚠️
The card is never recoloured by a colour variant, unlike Flex Carousel's generic placeholder (which tints/blurs to match). Every .ufs-tile type already has an established look from tiles-spec.html that's reused everywhere else in the DS — changing it per-carousel-variant would break that consistency for no real benefit, since it's opaque, real content rather than a colour-matched placeholder. It stays a plain white card, border and all, on every background — including --image, over a photo. Colour Variants below get their visual variety from swapping the tile type itself per background, not from recolouring one fixed type.
Behavior

Pagination & Arrows

Identical mechanics to Flex Carousel: dynamic "shrinking window" dots (active pill, two near dots, one far, one at the edge, everything beyond collapses away), cached scroll-step geometry for smooth touch response, and initFlexCarousel() called on this component's root exactly as-is — no new JS, no renamed function. It queries .ufs-carousel-track/-dots/-arrow--prev/-arrow--next/-card inside whatever root it's given, so it doesn't need to know or care that the root is a .ufs-banner-carousel instead of a .ufs-flex-carousel.

JS — same function, called on both root selectors
JS
function initFlexCarousel(root) {
  var track = root.querySelector('.ufs-carousel-track');
  var dotsWrap = root.querySelector('.ufs-carousel-dots');
  var prevBtn = root.querySelector('.ufs-carousel-arrow--prev');
  var nextBtn = root.querySelector('.ufs-carousel-arrow--next');
  if (!track || !dotsWrap) return;
  var cards = Array.prototype.slice.call(track.querySelectorAll('.ufs-carousel-card'));
  // … measure / render / goTo — unchanged, see flex-carousel-spec.html
}
// Runs once per page load, covering every instance of either component
document.querySelectorAll('.ufs-flex-carousel, .ufs-banner-carousel').forEach(initFlexCarousel);
💡
Because measure() reads actual rendered card positions rather than a hardcoded width, the fact that Banner Carousel's cards (320px, real .ufs-tile content) are a different size from Flex Carousel's own placeholder (270px) needs zero special-casing — the same function measures whatever it finds.
⚠️
One deliberate visual difference from Flex Carousel's own .is-compact state, reusing the identical trigger (the same initFlexCarousel(), unmodified — no new measurement logic). Flex Carousel centres its cards within the row, which stays full-width. Banner Carousel instead drops __carousel's flex:1 growth and centres __panel + __carousel together as one content-width group. This is a purely visual choice, not a different condition: "the tiles fit without scrolling" and "panel + gap + the tiles' own full width isn't wider than the viewport" are the same test algebraically, since __carousel's available width is always viewport − panel − gap. __foot (dots/arrows) is hidden entirely in this state, same as Flex Carousel — nothing to page through, nothing needs to be shown.
Responsive

Desktop vs. Mobile

Below 768px, .ufs-banner-carousel switches from a row to a column: __panel goes first, full width, centred text and a full-width CTA; __carousel follows, reclaiming the full bled width on both edges (unlike desktop's trailing-only bleed — see Anatomy). The carousel's own mobile behaviour — arrows hidden, dots centred and take over as the only control — is identical to Flex Carousel's mobile treatment, unchanged.

Variants

Colour Variants

Same 4 options as Flex Carousel, same mechanism — a pure custom-property swap on the root, no rule duplication: default (white, Recipe Tile, shown above), --squid (squid-ink), --mushroom (mushroom-100), and --image (full-bleed photo + dark overlay). Only __panel's title/description and the dots/arrows respond to the variant's colour tokens — the primary CTA stays a plain filled button on every background, unaffected. The examples below also each swap in a different real .ufs-tile type — Product on --squid, Training on --mushroom, Article on --image — to demonstrate the "different tile types, same engine" flexibility in context, not because any variant requires a specific type. The tile itself is still never recoloured by the variant; see the notice in Card Content.

Variants

Content Combinations

In __panel, only __logo is optional — __title, __desc and the primary CTA are all required, every instance. This is stricter than Campaign Hero (where description is optional too): a Banner Carousel panel is always meant to introduce the carousel next to it, and a title alone doesn't do that. The carousel side has no optional pieces either: a track with at least one card, dots and both arrows are all part of the anatomy whenever __carousel is present, and every card should carry complete .ufs-tile information (image, title, rating, meta) — not a stripped-down placeholder.

Internationalisation

i18n & RTL

Identical technique to Flex Carousel: __panel and __carousel re-order automatically under dir="rtl" via plain flexbox (no explicit row-reverse needed) — the panel visually moves to the right, the carousel to the left. Only the physical bleed/margin/padding properties need explicit flips, same set as Flex Carousel plus one more for the panel-side bleed direction.
