Title

Eyebrow + heading + description block used to open a catalog, listing, or promotional page. Centred by default, with left-aligned, heading-size, and background colour modifiers, documented for implementation.

Source
template-catalog.html
Format·HTML + CSS
Overview

Full Component Preview

A single <section class="ufs-title-section"> — an uppercase eyebrow, a heading, and a short description, centred and width-capped for readability. It opens a catalog or listing page above a filters panel or tiles grid — see handover/template-catalog.html for it in that context — and doubles as a lightweight promotional block via its background modifiers (see Background below).

Structure

Anatomy

.ufs-title-section is always full width, with viewport-driven left/right padding (96px desktop, 16px mobile) — not a max-width cap. The 720px reading-width cap and centring live one level in, on .ufs-title-section__inner, which every instance wraps its content in. Inside that: an uppercase eyebrow (__eyebrow, text-overline sizing, accessible-orange), a heading (__heading, <h2> by default), and a body-copy description (__desc). No background or border of its own by default — it sits flush on whatever section contains it.

💡
Only the heading is required. __eyebrow and __desc are both optional — omit either (or both) when there's no eyebrow label or supporting copy for a given instance. No CSS changes needed either way: each is a plain sibling element, so removing one just removes its reserved --space-3 gap along with it.
⚠️
__inner is not optional the way __eyebrow/__desc are. Without it, content spans the full padded width with no reading-width cap — fine for a very short heading, but description text will run edge-to-edge on wide viewports.

Variants

Alignment

Default is centred, with the block itself auto-margined to the middle of its container. .ufs-title-section--left drops the centring and left-anchors both the text and the block — for use above a left-aligned grid or when the Title sits inside a wider asymmetric layout.

Default — centred

Variants

Heading Size

Default heading is a real <h2>, sized at the h2 scale. When Title sits lower in a page's heading hierarchy — nested inside another section that already opened with its own h2 — use an actual <h3> tag with the --h3 modifier class instead, which steps the size down to match. This is a semantic tag change, not just a visual one: pick the level that keeps the page's heading order correct, then apply the matching modifier.

Default — <h2>, h2 scale

Variants

Background

Two colour modifiers turn Title into a self-contained block with its own background, for use as a lightweight promotional or divider block rather than a plain in-flow page heading. --dark uses the squid-ink brand colour and flips the heading/description to salt for contrast (the eyebrow keeps its orange accent on both). --mushroom uses the light mushroom-100 surface and keeps the default dark text.

Variants

Page-Top Padding

When Title is the page's opening element — sitting directly beneath the breadcrumb, with no hero or banner above it — the default top padding (--space-16 desktop / --space-12 mobile) leaves too much air on top of content that's already been pushed down by the header and breadcrumb. Add .ufs-title-section--page-top to reduce top padding only, to --space-8 desktop / --space-4 mobile. Left/right/bottom padding are unaffected. Used in template-catalog.html and template-inspiration.html.

⚠️
Only apply this to a Title that opens a page. A Title used mid-page (e.g. a section title further down, like in template-product-bin.html or template-landing.html) should keep the default padding — it isn't sitting directly under a breadcrumb and needs its own breathing room from the content above it.
Default padding-top

/* Add this line INSIDE the existing .ufs-title-section
   @media (max-width: 768px) block — not as its own separate
   media query. Both rules share the same specificity (one class),
   so whichever one is later in the cascade wins; the base rule's
   `padding` shorthand always resets padding-top too, so a
   standalone query placed before it gets silently overridden. */
@media (max-width: 768px) {
  .ufs-title-section { padding: var(--space-12) var(--space-4) var(--space-4); }
  /* … other base mobile rules … */
  .ufs-title-section--page-top { padding-top: var(--space-4); }
}

Internationalisation

i18n & RTL

The centred default and both background modifiers are direction-agnostic — text-align: center and a background colour need no flip under dir="rtl". Only the --left modifier uses a physical value (text-align: left) and needs an explicit override to become right-aligned in RTL.

Default — centred, unaffected by dir="rtl"
