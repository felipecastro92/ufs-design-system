Account Tabs & Layout

The shared frame of every My Account page: breadcrumb, the four-tab section bar, and the two-column grid (main column + sidebar) the profile cards sit in. Plus the sub-page variant used by Order detail.

Structure

Account Tabs

A fixed set of four sections, always in this order: Overview · My profile · My Orders · My Favourites. Each tab is a link to its own page, so a full page load and not a panel switch. The current page's tab is marked active and isn't a link. Tab styling is the design system's .ufs-tabs component (see the Tabs section of the design-system doc). The only addition here is text-decoration: none, because three of the four tabs are real <a> links.

Structure

Two-Column Grid

A flexible main column plus a fixed-width sidebar on the right, top-aligned (align-items: start), so the two columns keep their own heights. Each column stacks its cards vertically. The sidebar narrows once before the layout collapses to a single column. On a single column, the sidebar content follows the main column, in DOM order.

Sub-page (Order detail)

A page opened from a tab, not a tab itself. It has no tab bar: a back link returns to the parent tab instead. The breadcrumb gains a third level (Home › My Account › Order: UFS-84903-4). Its grid is mirrored compared with the tabbed pages: a fixed 393px column on the left (order summary) and a flexible column on the right (order items). It collapses to one column at the same 1023px breakpoint.

Implementation

Accessibility & Open Items

Things the prototype does not settle yet. Worth deciding before this is built.

⚠️
Tab semanticsThe prototype marks the bar up as ARIA tabs (role="tablist" / role="tab" / aria-selected), but the tabs are links to other pages. ARIA tabs promise arrow-key switching between panels on the same page, which doesn't happen here. Recommended: use <nav aria-label="My Account"> with plain links, mark the current one with aria-current="page", and drop the tab roles. The visual design stays the same.
⚠️
Missing statesThe tabs have no hover style and no visible keyboard-focus style, and the back link's arrow button has no focus style either. Both need a design decision. Suggestion: hover to --color-brand-dark, and focus to the 2px outline used on other links.
⚠️
Back linkThe sub-page back link is two separate controls (arrow button + text link) going to the same place, so keyboard users hit two focus stops. Recommended: one <a> containing both the arrow icon and the label.
ℹ️
Skip linkThe <main> here is the "Jump to content" target (see nav-header-spec). It needs id="main-content" and tabindex="-1", as in the Anatomy markup above.
Implementation

RTL

No RTL-specific rules needed. The tab row is flexbox and the grid is CSS grid, so under dir="rtl" the tabs run right to left and the sidebar moves to the left automatically. The back arrow should be mirrored (point right) in RTL. The prototype doesn't do that yet.
