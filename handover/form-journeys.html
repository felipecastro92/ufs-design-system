Form Journeys

Every side-panel form in the design system reduces to two journeys — Account Creation and Opt-In — plus two standalone password flows. This document specifies the base version of each journey once, then lists exactly how each real trigger modifies it: which fields it adds or drops, what copy changes, and what happens once the form succeeds.

Opt-In journey

Captures contact details and marketing consent without necessarily creating an account. Shorter than Account Creation — no password, no verification code — and, unlike that journey, it's the one place where account creation can be reached from it, as an explicit next step, rather than the other way around.

Display rule — Business typeBefore a Business type is chosen, Business name, Job title and Mobile number are hidden. Selecting Hotel, Restaurant, School canteen, Catering or Other reveals all three together, in that order, right below Business type. Selecting "I don't have/work in a business" keeps them hidden, or hides them again if they were showing, along with any business card or address fields Business name had revealed. Hidden fields never block the form's submit button. Whatever was typed is kept and comes back if a business option is chosen again.
ℹ️
Author setting — Job title & Mobile numberThe page author decides, per field and per form, whether Job title and Mobile number are optional or mandatory. Each one is set on its own, so either, both or neither can be mandatory.
  • Optional: the label ends in "(optional)". A blank value is valid and never blocks the submit button.
  • Mandatory: no "(optional)" suffix. The submit button stays disabled until the field has a value.

Either way, the setting only applies while the field is shown. If "I don't have/work in a business" hides it, it is never required. A malformed Mobile number blocks the submit button in both modes.

Additional information step — optional

Any Opt-In form can add one extra step to collect something the shared field set doesn't cover. This is the Opt-In counterpart of Account Creation's additional information step. Forms without it go straight from Details to Success.

  • Content is form-specific. The page author picks the questions, for example a free-text message, a product selection or a quiz. Every question is mandatory. Types and rules: see Additional questions in the appendix.
  • The shared field set stays in Step 1. Nothing from the Details form moves into this step, and none of its fields (Business name included) are asked again here.
  • Position: after the Details form. The one exception is Request a sample, which places it first (pick products → Details form → Success).
  • Buttons: whichever of the two steps comes first reads Continue. The form's final action (e.g. Submit) sits on the step that comes second, disabled until its required fields are filled in.
  • Signed-in users skip the Details form, since their details are already on file, and open straight on the Additional information step. Its button then carries the final action.
  • Heading: keeps the form's own title, with a one-line subtitle that introduces the step.
  • Success screen: up to each form. It may summarise what was entered in this step (e.g. the chosen products), or not.

Live example: Contact us, whose Additional information step is a single Message field.

Shared Patterns

Password rules

Used in: Account Creation — Password stepForgot password — New password stepChange password

Every password field in the system is a single input — there is no re-type/confirm field anywhere — gated by the same three live-updating checklist rules:

At least 8 characters
At least 1 uppercase letter
At least 1 number

Each rule turns green as it's met. The submit button — "Create account", "Reset password", or "Save password" depending on where this appears — stays disabled until all three pass.

Shared Patterns

Verification code

Used in: Account Creation — Regular, Unlock content, Access functionalityForgot password

6 individual digit boxes, auto-advancing as each is typed, pasting a full code fills all six at once. A Resend code link stays disabled for 59 seconds after the code is sent, counting down visibly. "Not your email/mobile number? Change it" returns to the contact-entry step, discarding everything since. Copy switches between an email-flavoured and an SMS-flavoured variant depending on which contact method is being verified — e.g. "Check your email" vs. "Check your phone" — and, on the Forgot password journey, to a reset-flavoured variant ("…to reset your password") instead of a verify-flavoured one.

Shared Patterns

Additional questions

Used in: Account Creation — additional informationOpt-in — Additional information step

Questions a form asks on top of its journey's own fields, when a scenario needs information that neither Account Creation nor Opt-In collects. The page author decides how many questions there are, their order, their wording and their type. Any mix of the six types below can be used, and the same type can appear more than once.

Rules for every question

  • Always mandatory. No question can be made optional, and none carries an "(optional)" suffix. The step's final button stays disabled until every question has a valid answer.
  • Label = the question, written by the author. No automatic numbering. A one-line hint can sit under the field when it helps (e.g. the accepted file types).
  • No conditional questions. Every question the author adds is always shown. The one exception is an "Other" option in a multiple- or single-selection question, which reveals a text input for the person to specify; that text input is then mandatory too.
  • Errors appear inline under the field they belong to, and clear as soon as the answer is fixed.

File upload — behaviour

  • The picker reads e.g. "Choose a file" and the hint underneath lists the accepted types (e.g. "JPG, PNG or HEIC photo of your receipt").
  • Several files can be added to the same question. Each attached file is listed by its name with its own remove (×) button; removing the last one makes the question unanswered again.
  • The accepted types are checked when a file is picked, not only by the picker's filter. A file of any other type is not attached, and the hint turns into an inline error, e.g. "This file isn't an image. Please upload a JPG, PNG or HEIC photo."
  • A form can have more than one file-upload question.
