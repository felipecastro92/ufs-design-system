Form Journeys

Every side-panel form in the design system reduces to two journeys — Account Creation and Opt-In — plus two standalone password flows. This document specifies the base version of each journey once, then lists exactly how each real trigger modifies it: which fields it adds or drops, what copy changes, and what happens once the form succeeds.

Account Creation journey

Turns an anonymous visitor into a signed-in account. Every trigger below opens the same five-step panel and ends the same way — signed in — but each is reached from a different place for a different reason, and three of them modify the base flow to fit that reason.

💡
Placement ruleCountry selector, multi-country scenarios only: when a form in this journey needs to ask which country the person is in, the Country dropdown sits immediately after Last name — before Mobile number, Business type, or anything else. No Account Creation trigger currently asks for country, so there's no live example of the rule inside this journey yet; when one is added, this is where it goes. Trigger: "Request a sample" button, product page hero

Same panel as Regular account creation, with the differences below — including one fewer step, since this trigger skips verification.

    Step 1 heading changes

    Reads Sign in or Create an account to Request Sample instead of the generic heading — and if the person is already signed in, the whole panel is skipped and they land directly on the consulting-needs questions below.

  • 2

⚠️
Known divergenceOn this trigger, account registration skips the verification-code step entirely — for both Email and Mobile number. Whichever contact method was given goes straight to Account details, unverified. Every other Account Creation trigger verifies the contact method with a code first.

03Account creation to unlock content

Trigger: "Start Training Now" (course hero) or any locked video's play button

Identical to Regular account creation start to finish — same heading, same fields, same copy. The only difference is what happens after Success.

  • 1
    Every locked module unlocks at once

    The moment sign-in completes, all locked videos on the page unlock together — not just the one the person clicked — and both the hero and sticky "Start Training Now" buttons disappear, since there's nothing left to unlock. The person clicks the module again to actually play it; nothing auto-plays.

⚠️
Known divergenceThis "unlock everything at once" behaviour is specific to this trigger. Compare with Access functionality below, where only the single item the person acted on completes automatically.

04Account creation to access functionality

Trigger: Favourite (heart) button, recipe hero

Same five steps as Regular account creation, with the differences below.

  • 1
    Step 1 heading and description change

    Heading: Sign up or Log in to create your own personal recipe book. A description appears underneath, which the generic entry point doesn't show: Join over 1 million chefs already getting inspired.

  • 2
    The favourite completes itself

    Once sign-in finishes — by creating an account or by logging in — the recipe the person originally tried to favourite is favourited automatically. They never have to click the heart a second time.

Shared Patterns

Password rules

Used in: Account Creation — Password stepForgot password — New password stepChange password

Every password field in the system is a single input — there is no re-type/confirm field anywhere — gated by the same three live-updating checklist rules:

At least 8 characters
At least 1 uppercase letter
At least 1 number

Each rule turns green as it's met. The submit button — "Create account", "Reset password", or "Save password" depending on where this appears — stays disabled until all three pass.

Shared Patterns

Verification code

Used in: Account Creation — Regular, Unlock content, Access functionalityForgot password

6 individual digit boxes, auto-advancing as each is typed, pasting a full code fills all six at once. A Resend code link stays disabled for 59 seconds after the code is sent, counting down visibly. "Not your email/mobile number? Change it" returns to the contact-entry step, discarding everything since. Copy switches between an email-flavoured and an SMS-flavoured variant depending on which contact method is being verified — e.g. "Check your email" vs. "Check your phone" — and, on the Forgot password journey, to a reset-flavoured variant ("…to reset your password") instead of a verify-flavoured one.
