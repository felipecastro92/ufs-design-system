Overview

Full Component Preview

A self-contained, full-width section built from 3 stacked rows: a title + description + secondary CTA row, a horizontally-scrolling card track, and a pagination + arrow controls row. Every preview on this page is the real, working component — not a screenshot — so the arrows, dots and swipe behaviour below are fully interactive.

ℹ️
Card content/design is not final — the 10 cards below are placeholders (fixed 270×270, --color-mushroom-100, --radius-lg). The component doesn't care what's inside a card or how many there are; both are safe to change without touching the JS.
🧱
3-row structure
Head (intro + CTA), track (cards), foot (pagination + arrows) — each documented in its own section below.
📱
Independent mobile layout
Below 768px the CTA relocates below the track as a full-width block, arrows disappear, and only centred pagination remains — see Desktop vs. Mobile.
🎨
4 colour looks, 1 codebase

Structure

Anatomy — 3 Rows

The component is a single <section class="ufs-flex-carousel"> containing three direct row groups, always in this order. Live preview and full markup are above (Overview) — this is the complete reference code for the default look.

Row 1 — .ufs-flex-carousel__head
Title + optional description in .ufs-flex-carousel__intro (flex: 1, so it eats remaining width), plus the secondary CTA — aligned via align-items: flex-end so the shorter button sits flush with the baseline of the taller text stack.

Row 2 — .ufs-flex-carousel__track-wrap → .ufs-carousel-track
A horizontally-scrolling flex row. First child is an invisible .ufs-carousel-spacer (not a card — see Edge-to-Edge Bleed for why), followed by N .ufs-carousel-card placeholders.
Row 3 — .ufs-flex-carousel__foot
Pagination dots (.ufs-carousel-dots) on the left, arrow controls (.ufs-flex-carousel__arrows) on the right — justify-content: space-between. A second, mobile-only CTA (.ufs-flex-carousel__cta--mobile) sits after this row, hidden on desktop.

Pagination — Dynamic Bullets

Dots are entirely JS-generated at init — one <button class="ufs-carousel-dot"> per card, appended into the empty .ufs-carousel-dots container. Every property (width, height, colour, opacity) transitions, so re-rendering the states below animates the whole row rather than snapping between states. Click any dot in the live preview above (Overview) to see it — or use the arrows, which drive the same state.

Behaviour

Edge-to-Edge Bleed

The card track visually breaks out of the section's own padding on both sides — the first card still lines up with the title on the left, but as you scroll, cards travel all the way to the true screen edge (not just the section's padded content edge) before disappearing, on both directions. This took two non-obvious fixes to get right; both are documented here so they don't get "cleaned up" by accident later.

1. The bleed itself
.ufs-flex-carousel__track-wrap cancels the section's own left/right padding with negative margins equal to it, letting its box reach the true edges. .ufs-carousel-track then restores the padding inside itself — as padding-right on the trailing edge (browsers respect this fine on a scroll container) — but not as padding-left.
2. Why the leading edge needs a spacer, not padding-left
Chromium doesn't honour a scrollable flex container's start-edge padding the way it does the end edge — it silently offsets the initial scrollLeft instead of reserving visual space, which makes the first card render flush with the true edge (not aligned with the title) at rest. The fix is a real flex-item spacer (.ufs-carousel-spacer) as the track's first child instead — spacers aren't subject to this quirk.

Interaction & Scroll

One self-invoking script initialises every .ufs-flex-carousel found on the page independently (document.querySelectorAll(...).forEach(initFlexCarousel)) — drop in a second instance (e.g. a colour variant) and it just works, no extra wiring.

Scroll granularity
One card at a time. stepSize() measures the live distance between the first two rendered cards (not a hardcoded width + gap), so it stays correct even if card size or spacing changes. An arrow click or dot click calls track.scrollTo({ left: index * stepSize(), behavior: 'smooth' }).
Bounds
maxIndex() derives the last valid stop from track.scrollWidth - track.clientWidth divided by the step — not from card count — so it also adapts if the viewport is wide enough to show most/all cards already (fewer, or zero, reachable stops).
Swipe / native scroll
The track is a plain overflow-x: auto element — touch swipe and trackpad scroll work natively, no custom drag JS. A scroll listener keeps the pagination in sync, throttled with requestAnimationFrame rather than a post-scroll debounce, so dots track the gesture live instead of updating only once it settles (important on mobile, where the dots are the only visible control since arrows are hidden there).
JS
    (function() {
              function initFlexCarousel(root) {
                var track = root.querySelector('.ufs-carousel-track');
                var dotsWrap = root.querySelector('.ufs-carousel-dots');
                var prevBtn = root.querySelector('.ufs-carousel-arrow--prev');
                var nextBtn = root.querySelector('.ufs-carousel-arrow--next');
                if (!track || !dotsWrap) return;
                var cards = Array.prototype.slice.call(track.querySelectorAll('.ufs-carousel-card'));
                var activeIndex = 0;
                var scrollTicking = false;

                function stepSize() {
                  if (cards.length < 2) return cards.length ? cards[0].getBoundingClientRect().width : 0;
                  return cards[1].getBoundingClientRect().left - cards[0].getBoundingClientRect().left;
                }
                function maxIndex() {
                  var step = stepSize();
                  if (!step) return 0;
                  /* signed step is negative in RTL — divide by magnitude */
                  return Math.max(0, Math.round((track.scrollWidth - track.clientWidth) / Math.abs(step)));
                }
                function render() {
                  var maxI = maxIndex();
                  var dots = dotsWrap.querySelectorAll('.ufs-carousel-dot');
                  dots.forEach(function(dot, i) {
                    dot.classList.remove('is-active', 'is-near', 'is-far', 'is-edge', 'is-hidden');
                    if (i > maxI) { dot.classList.add('is-hidden'); return; }
                    var dist = Math.abs(i - activeIndex);
                    if (dist === 0) dot.classList.add('is-active');
                    else if (dist <= 2) dot.classList.add('is-near');
                    else if (dist === 3) dot.classList.add('is-far');
                    else if (dist === 4) dot.classList.add('is-edge');
                    else dot.classList.add('is-hidden');
                    dot.setAttribute('aria-current', dist === 0 ? 'true' : 'false');
                  });
                  if (prevBtn) prevBtn.disabled = activeIndex <= 0;
                  if (nextBtn) nextBtn.disabled = activeIndex >= maxI;
                }
                function goTo(index) {
                  activeIndex = Math.max(0, Math.min(maxIndex(), index));
                  track.scrollTo({ left: activeIndex * stepSize(), behavior: 'smooth' });
                  render();
                }

                cards.forEach(function(_, i) {
                  var dot = document.createElement('button');
                  dot.type = 'button';
                  dot.className = 'ufs-carousel-dot';
                  dot.setAttribute('aria-label', 'Go to item ' + (i + 1));
                  dot.addEventListener('click', function() { goTo(i); });
                  dotsWrap.appendChild(dot);
                });
                if (prevBtn) prevBtn.addEventListener('click', function() { goTo(activeIndex - 1); });
                if (nextBtn) nextBtn.addEventListener('click', function() { goTo(activeIndex + 1); });

                /* rAF-throttled so the pagination (and, on mobile, that's the only
                   visible control since arrows are hidden there) tracks a touch
                   swipe live as it happens, not just after the gesture/momentum
                   settles — a post-scroll debounce reads as "not reflecting" the
                   swipe on a real device. */
                track.addEventListener('scroll', function() {
                  if (scrollTicking) return;
                  scrollTicking = true;
                  requestAnimationFrame(function() {
                    var step = stepSize();
                    if (step) activeIndex = Math.max(0, Math.min(maxIndex(), Math.round(track.scrollLeft / step)));
                    render();
                    scrollTicking = false;
                  });
                }, { passive: true });

                window.addEventListener('resize', function() { render(); });
                render();
              }

              document.querySelectorAll('.ufs-flex-carousel').forEach(initFlexCarousel);
            })();

Internationalisation

i18n & RTL

Because the carousel scrolls horizontally, it fully mirrors under dir="rtl" — the same principle applied across the nav and footer. Cards rest at the right and advance leftward, the arrow pair swaps sides and flips its chevrons, and pagination mirrors. No markup changes: set dir="rtl" on any ancestor (the page sets it on <html>) and both the CSS and the scroll JS adapt.

What mirrors (and how)
Most of the layout re-orders on its own via flex/grid; only a few physical properties need an explicit flip.
Head rowautomatic (flex)title/description align right, CTA moves to the left
Card orderautomatic (flex)first card rests at the right, advances leftward

ℹ️
The horizontal-scroll JS needs almost nothing: Chromium reports a negative scrollLeft in RTL, and stepSize() is already signed (negative when mirrored), so goTo() and the scroll-sync math cancel out in both directions. The only guard is maxIndex() dividing by Math.abs(step) — see Interaction & Scroll. No dir-detection branch, no separate RTL code path.
💡
Unlike the footer's email field (which stays dir="ltr"), nothing in the carousel needs to opt out of mirroring — the cards carry localised content and everything else is directional chrome. The title, description and CTA carry data-i18n hooks (carousel-title, carousel-desc, carousel-cta) so their copy switches with the active language — without them the text stays English and, in Arabic, renders as Latin glyphs in the Arabic font (i.e. the type looks unchanged). Card content should localise the same way; the placeholder cards here have none. The RTL preview above uses Arabic sample copy to make the mirrored alignment obvious.
