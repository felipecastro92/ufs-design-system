Campaign Hero

Full-bleed marketing hero with a looping background video or a static image, a darkening overlay for text contrast, and a centred content column — optional logo, mandatory title, optional description, optional countdown, mandatory primary CTA, optional secondary CTA, optional disclaimer. Structure, background variants and responsive rules, documented for implementation.

Source
full-page-preview-v0.2.html
Format·HTML + CSS
Overview

Full Component Preview

A single <section class="ufs-campaign-hero"> — a full-bleed background (looping <video> or static <img>, both object-fit: cover), a darkening overlay for contrast, and a centred 720px content column: an optional logo, a title, an optional description, an optional countdown, a primary CTA, an optional secondary CTA, and an optional disclaimer. Every layout rule is centred/symmetric on both axes, so mobile and RTL need no structural overrides — only type-scale and spacing change responsively (see Desktop & Mobile Layout below).

Structure

Anatomy

Two top-level children of .ufs-campaign-hero: __media (an absolutely-positioned <video> or <img> plus __overlay, both filling the section) and __content (everything else, centred and capped at 720px — same reading-width convention as .ufs-title-section__inner). Inside content: __logo, a __heading wrapping __title/__desc, then __countdown, __ctas and __disclaimer as content's other direct children.

⚠️
The title is not built from .text-h2 or any other heading token — its 40px/28px size, 1.15 line-height and -0.4px/-0.28px letter-spacing are literal values from this component's own Figma spec (weight 900 and line-height 1.15 happen to match --text-h2-w/-lh, but the sizes don't match --text-h2-size at either breakpoint). Treat it as a bespoke hero scale, not a reusable token.
Structure

Desktop & Mobile Layout

Height is content-driven with a min-height floor, not a fixed height: min-height only sets a minimum, so if the optional content filled in (logo, description, countdown, both CTAs, disclaimer) runs longer than that floor, the section grows to fit rather than clipping — same principle as Promo Banner and Title. Desktop floor is a fixed 600px; mobile uses 70vh instead, since a fixed pixel floor that reads as "generous" on desktop can be excessive on a short phone viewport.

What changes at the 768px breakpoint
Everything else (centring, column structure, overlay, CTA row shrinking to a column) already reads correctly without any breakpoint-specific structural change.
min-height600px → 70vhfloor, not a cap — content can still push the section taller
padding--space-16 --space-4 → --space-10 --space-4top/bottom tightens on mobile
Logo180px → 150pxwidth, height auto
Title40px → 28pxletter-spacing also eases from -0.4px to -0.28px
Description--text-body-size → --text-body-sm-size16px → 14px
Countdown value--text-price-xl-size → -mob-size36px → 28px, at the 1024px breakpoint specifically — matches Promo Banner's own cutoff for the same property
CTAsrow → column, full widthboth buttons stack and stretch to 100% below 768px
💡
The countdown value's own size switch happens at min-width: 1024px, not the component's usual 768px cutoff — deliberately kept aligned with Promo Banner's own countdown breakpoint rather than this component's own, since the whole point of reusing .text-price-xl/.text-body-sm is that the two components' countdowns stay identical.
Variants

Background

.ufs-campaign-hero__media accepts either a looping <video> or a static <img> as its first child — both share the same position:absolute; inset:0; object-fit:cover rule, so no modifier class is needed to switch between them. The video uses two <source> elements so mobile and desktop can each get a differently-cropped export (portrait vs landscape) — evaluated in order, first matching media wins, unconditional source last as the fallback.

</div>

<!-- Static image — same __media wrapper, an <img> instead -->
<div class="ufs-campaign-hero__media" aria-hidden="true">
  <img src="background.jpg" alt="" />
  <div class="ufs-campaign-hero__overlay"></div>
</div>
⚠️
The video is muted, autoplaying and purely decorative (aria-hidden="true" on the wrapper) — a page's own script is expected to pause it for prefers-reduced-motion: reduce (see the DOMContentLoaded handler in full-page-preview-v0.2.html, which pauses any [data-campaign-hero-video] element under that media query rather than forcing autoplay on everyone regardless of that preference).

Internationalisation

i18n & RTL

Every rule on this component is either text-align: center or a symmetric inset/flex row-column centred on both axes — nothing physically left/right-coded. That means it mirrors correctly under dir="rtl" with zero CSS overrides, unlike Promo Banner's asymmetric image+panel split (which needs explicit flips — see promo-banner-spec.html). Live in full-page-preview-v0.2.html: the RTL instance sits directly below the English one.
