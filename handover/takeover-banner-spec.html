Takeover Banner

Full-page promotional dialog, centred over a dimmed/blurred backdrop — optional logo, mandatory title, optional description, optional live countdown, mandatory primary CTA, optional secondary CTA, optional disclaimer, mandatory close button. Structure, behavior and responsive rules, documented for implementation.

Source
New — Figma only
Format·HTML + CSS + JS
Overview

Full Component Preview

A single <div class="ufs-takeover-banner"> — a fixed, full-viewport dialog: a dimmed/blurred __backdrop behind a centred, bordered __panel carrying a background image, a darkening scrim, a close button, and a content column (logo, title, description, live countdown, primary + secondary CTAs, disclaimer). It opens over whatever page is currently showing, automatically on load by default — see Trigger & Auto-Open below.

💡
This preview opens on click, not automatically, so you can read the docs on this page without the takeover firing over them. In production, the component's own init script opens it on page load after a short delay — see data-auto-open.
ℹ️
Only the title, primary CTA and close button are required. Logo, description, countdown, secondary CTA and disclaimer are all optional — omit any of them per instance with no CSS changes needed. See Content Combinations below for a minimal instance with everything else stripped out.
Structure

Anatomy

Two top-level children of .ufs-takeover-banner: __backdrop (the dimmed/blurred full-viewport tint) and __panel (the visible card — bordered, rounded, shadowed, overflow: hidden). Inside the panel: __media + __scrim (an absolutely-positioned background image or video, darkened for text contrast — same two-layer technique as Campaign Hero's own __media/__overlay), a __close button, and __content — a centred 720px column holding __logo, a __heading wrapping __title/__desc, then __countdown, __ctas and __disclaimer.

⚠️
__content onward (logo/title/desc/countdown/CTAs/disclaimer) is the exact same recipe as .ufs-campaign-hero__content — same bespoke 40px/28px hero title scale, same body/countdown/disclaimer tokens, same .btn/.btn-on-dark CTA classes. This is deliberate: the two components share a content shape (a promotional message over darkened imagery) and should read identically wherever they appear. Only the outer chrome differs — Campaign Hero sits in the page's content flow; Takeover Banner is a fixed dialog on top of it.

Structure

Desktop & Mobile Layout

Panel size is content-driven with a min-height floor (480px desktop / 540px mobile), not a fixed height — same principle as Campaign Hero and Title. Below 768px the panel radius tightens, the CTA row stacks into a full-width column, and type scales down — everything else (centring, column structure, scrim) already reads correctly without further structural change.

Behavior

Trigger & Auto-Open

Mark the root data-auto-open and it opens itself automatically, 1.5 seconds after page load — long enough that it doesn't feel like it's blocking the page from rendering, short enough to still read as immediate. Only one takeover should be marked data-auto-open per page. A takeover without that attribute is inert until something else calls openTakeover() on it — e.g. a link or a scheduled campaign trigger.

JS — self-initializing on load
JS
document.addEventListener('DOMContentLoaded', function () {
  document.querySelectorAll('.ufs-takeover-banner[data-auto-open]').forEach(function (el) {
    setTimeout(function () { openTakeover(el); }, 1500);
  });
});
⚠️
This spec's own demo instance (see Overview) deliberately omits data-auto-open so it doesn't fire while you're reading — a "Preview the takeover" button calls openTakeover() directly instead. Production usage should use data-auto-open, not a manual trigger.
Behavior

Countdown

Set data-countdown-end (an ISO-8601 datetime) on the .ufs-takeover-banner__countdown block and give each digit a [data-tkb-unit] attribute. On load, initTakeoverCountdown() ticks every second toward that timestamp and freezes at 00:00:00:00 when it's reached — matching Announcement Banner's own countdown behavior, so a promotion ending doesn't cause a surprising layout shift or content loss right as a user is looking at it.

JS — self-initializing on load
Runs once per .ufs-takeover-banner__countdown found on the page.
JS
function initTakeoverCountdown(countdownEl) {
  var end = new Date(countdownEl.getAttribute('data-countdown-end')).getTime();
  var dayEl = countdownEl.querySelector('[data-tkb-unit="days"]');
  var hourEl = countdownEl.querySelector('[data-tkb-unit="hours"]');
  var minEl = countdownEl.querySelector('[data-tkb-unit="minutes"]');
  var secEl = countdownEl.querySelector('[data-tkb-unit="seconds"]');
  function pad(n) { return n < 10 ? '0' + n : '' + n; }
  function tick() {
    var diff = end - Date.now();
    if (diff <= 0) {
      dayEl.textContent = '00'; hourEl.textContent = '00'; minEl.textContent = '00'; secEl.textContent = '00';
      clearInterval(timer);
      return;
    }
    var totalSeconds = Math.floor(diff / 1000);
    dayEl.textContent  = pad(Math.floor(totalSeconds / 86400));
    hourEl.textContent = pad(Math.floor(totalSeconds % 86400 / 3600));
    minEl.textContent  = pad(Math.floor(totalSeconds % 3600 / 60));
    secEl.textContent  = pad(totalSeconds % 60);
  }
  tick();
  var timer = setInterval(tick, 1000);
}
document.querySelectorAll('.ufs-takeover-banner__countdown[data-countdown-end]').forEach(initTakeoverCountdown);
⚠️
Accessibility — do not make the countdown an aria-live region. A per-second announcement would be read aloud continuously by screen readers. The digits update visually only; the surrounding role="dialog"/aria-labelledby and the CTAs remain the actionable, announced part — same rule already documented for Announcement Banner.
Behavior

Dismiss

Three ways to close: the __close button, the Esc key, or clicking the dimmed backdrop outside the panel. All three call the same closeTakeover(). Dismissal is session-only — there's no localStorage/cookie persistence, so the takeover opens again from scratch on the next full page load. That's a deliberate simplicity trade-off, the same one already made for Announcement Banner; per-instance "don't show again for N days" is a reasonable future extension if a specific campaign needs it.

JS — open / close, wired once per instance
JS
function openTakeover(el) {
  el.classList.add('is-open');
  document.body.style.overflow = 'hidden';
  var closeBtn = el.querySelector('.ufs-takeover-banner__close');
  if (closeBtn) closeBtn.focus();
}
function closeTakeover(el) {
  el.classList.remove('is-open');
  document.body.style.overflow = '';
  document.activeElement.blur();
}

document.querySelectorAll('.ufs-takeover-banner').forEach(function (el) {
  var backdrop = el.querySelector('.ufs-takeover-banner__backdrop');
  var closeBtn = el.querySelector('.ufs-takeover-banner__close');
  closeBtn.addEventListener('click', function () { closeTakeover(el); });
  backdrop.addEventListener('click', function () { closeTakeover(el); });
});
document.addEventListener('keydown', function (e) {
  if (e.key !== 'Escape') return;
  document.querySelectorAll('.ufs-takeover-banner.is-open').forEach(function (el) { closeTakeover(el); });
});
💡
Focus on open/close: opening moves focus to the close button (the natural first stop in a dialog with no form field); closing blurs the active element first, matching the pattern already documented for Announcement Banner's close button, so focus never dangles on a control that's about to become inert.
Variants

Background

__media accepts either a static <img> or a looping <video> as its first child — same position:absolute; inset:0; object-fit:cover rule as Campaign Hero's own __media, so no modifier class is needed to switch between them.

⚠️
The Figma reference for this component (the "Future Menus" campaign) layers 5-6 separate photos into a hand-built collage behind the card. That's bespoke art direction for one campaign's creative, not part of the reusable component — __media takes a single flattened image (or video) export, the same contract as Campaign Hero's background.

Internationalisation

i18n & RTL

Layout is direction-agnostic by construction: everything is centred flexbox, and the one offset that matters — the close button's corner position — uses inset-inline-end rather than a physical right, so it flips to the visual left automatically under dir="rtl" with no separate override rule needed. Route every visible string through the same data-i18n mechanism as the rest of the header/footer/Announcement Banner.
