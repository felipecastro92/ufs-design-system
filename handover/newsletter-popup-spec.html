Design System / Newsletter Popup
Handover Spec

Newsletter Popup

Lead-capture dialog, centred over a dimmed/blurred backdrop — left info panel (mandatory title, optional description, mandatory email field + Continue button) and a right full-bleed image, stacking on mobile like Promo Banner. Mandatory close button. Structure, behavior and responsive rules, documented for implementation.

Overview

Full Component Preview

A single <div class="ufs-newsletter-popup"> — a fixed, full-viewport dialog: a dimmed/blurred __backdrop behind a centred, white __card carrying a close button, an info panel (title, description, email field, Continue button) and a full-bleed image. It opens over whatever page is currently showing, automatically on load by default — see Trigger & Auto-Open below.

💡
This preview opens on click, not automatically, so you can read the docs on this page without the popup firing over them. In production, the component's own init script opens it on page load after a short delay — see data-auto-open.
ℹ️
Title, the email field + Continue button, and the close button are required. Description is optional — omit it per instance with no CSS changes needed. Unlike Promo Banner and Takeover Banner, there's no logo, countdown, secondary CTA or disclaimer slot — this component's anatomy is intentionally narrower, built for one job: capturing an email address.
Structure

Anatomy

Three children of .ufs-newsletter-popup's __card: a __close button, a __panel (left info column) and an __image (right full-bleed photo) — the same two-region split as .ufs-promo-banner's __panel/__image, just renamed onto this component's own class. Inside the panel: a __heading wrapping __title/__desc, then a __form holding the email __input and a Continue .btn.btn-primary.

⚠️
At desktop, __image's size, position and radius are mirrored 1:1 from Promo Banner's own __image — same "nested pill" technique, same values: pulled out of flow, 12px taller than the panel on both edges, starting 3% inside the panel's own width, with a large radius accent on the corner that overlaps it. __card deliberately carries no overflow: hidden, for the same reason Promo Banner's own container doesn't clip its children — it's what lets the 12px bleed and the full radius curve render uncropped, past the card's own top/bottom edge, instead of being clipped flush to it. The trade-off: this component now has no scroll safety net for very short viewports, the same as Takeover Banner's own dialog (see the notice in Desktop & Mobile Layout below).
ℹ️
__image is the last DOM child (after __close and __panel), on purpose: the base (mobile) __card is display: flex; flex-direction: column-reverse, which puts the last child first visually — image on top, panel below, matching Promo Banner's own mobile stacking — without reordering the markup itself. Reading and focus order stay close → panel → image; only the visual stack reverses. At the 1024px breakpoint, __image switches to position: absolute (see the warning above) and is taken out of flex flow entirely, leaving __panel as the row's only flex item — pinned to the visual left by flex-direction: row, with the image's own left: 49% placing it on the right. Unlike the mobile stacking swap, this positioning is physical (not flex order), so it needs its own explicit flip under dir="rtl" — see i18n & RTL below.

Structure

Desktop & Mobile Layout

Mobile-first, same 1024px breakpoint as Promo Banner. Below it, the card stacks: image on top at a fixed 390:295 aspect ratio (identical to Promo Banner's mobile image), panel below in normal flow, everything centred. At 1024px and up, the card becomes a flex row and __image is pulled out of flow the same way Promo Banner's own image is — panel takes a fixed 52%, and the image is absolutely positioned to fill the remaining 48%, 12px taller than the panel and starting 3% inside its width (see the Anatomy warning above for the full "nested pill" recipe and how it differs from Promo Banner's un-clipped version). The card's own min-height: 520px only applies at that breakpoint; on mobile, height is content-driven exactly like Promo Banner (no forced minimum), which is why this component doesn't carry a mobile min-height the way Takeover Banner's panel does.

⚠️
__card has no max-height/overflow-y: auto scroll safety net — a deliberate trade-off, not an oversight. Promo Banner never needs one (it lives in normal scrollable page flow), and adding one here would clip the 12px image bleed described in the Anatomy warning above, since any non-visible overflow value clips to the box regardless of whether it triggers a scrollbar. This matches Takeover Banner's own dialog, which carries the same trade-off for the same reason. On a very short viewport (e.g. a landscape phone) the card can in principle exceed the viewport height with no way to scroll to what's cut off — acceptable here given the fixed, short copy, but worth flagging if this component's content is ever made longer or more variable.
Behavior

Trigger & Auto-Open

Mark the root data-auto-open and it opens itself automatically, 1.5 seconds after page load — identical timing and mechanism to Takeover Banner, so the two full-page dialogs behave consistently if a page ever needs to choose between them. Only one popup should be marked data-auto-open per page. A popup without that attribute is inert until something else calls openNewsletterPopup() on it.

JS — self-initializing on load
JS
document.addEventListener('DOMContentLoaded', function () {
  document.querySelectorAll('.ufs-newsletter-popup[data-auto-open]').forEach(function (el) {
    setTimeout(function () { openNewsletterPopup(el); }, 1500);
  });
});
⚠️
This spec's own demo instance (see Overview) deliberately omits data-auto-open so it doesn't fire while you're reading — a "Preview the popup" button calls openNewsletterPopup() directly instead. Production usage should use data-auto-open, not a manual trigger. If a page also runs a Takeover Banner with data-auto-open, don't fire both — pick one lead-capture/promo dialog per page load.
Behavior

Email Form

A single <input type="email" required> paired with a submit button, same overall shape as Footer's newsletter band — but two deliberate departures from that pattern, documented below. The form calls npSubmitEmail(event) on submit; wire the real subscribe request there, same integration point as Footer's own nlSubmitFooterEmail().

⚠️
Where this differs from Footer's newsletter band: (1) the input/button are --space-12 (48px) tall, reusing the DS's existing .fi-field sign-in input treatment (mushroom-100 fill, mushroom-700 border) — not Footer's bespoke 54px mushroom-100-on-orange pair, which only exists because that band's background is orange and its button needs a ghost-on-orange ($1px salt border) treatment to read. (2) the Continue button is the shared .btn.btn-primary component, not a bespoke class — same reuse-the-CTA-component approach as Promo Banner and Takeover Banner. Footer's own spec explicitly calls out that its pair does not use .btn/form-field; that's a footer-local exception, not a rule to carry forward here.
JS — submit handler (presentational stub)
JS
function npSubmitEmail(event) {
  event.preventDefault();
  var form  = event.target;
  var input = form.querySelector('.ufs-newsletter-popup__input');
  // Wire the real subscribe request here — this stub only
  // validates and closes the dialog on success.
  if (!input.checkValidity()) { input.reportValidity(); return false; }
  closeNewsletterPopup(form.closest('.ufs-newsletter-popup'));
  return false;
}
💡
Opening the dialog focuses the email input, not the close button — the opposite of Takeover Banner. That's not an inconsistency: Takeover Banner's own Dismiss section already scopes its focus-the-close-button rule to "a dialog with no form field." This component has one, so the same rule sends focus to it instead, for a faster type-and-submit flow.
Behavior

Dismiss

Three ways to close: the __close button, the Esc key, or clicking the dimmed backdrop outside the card. All three call the same closeNewsletterPopup() — identical mechanism to Takeover Banner. Dismissal is session-only; there's no localStorage/cookie persistence, so the popup opens again from scratch on the next full page load, the same simplicity trade-off already made for both Takeover Banner and Announcement Banner.

JS — open / close, wired once per instance
JS
function openNewsletterPopup(el) {
  el.classList.add('is-open');
  document.body.style.overflow = 'hidden';
  var input = el.querySelector('.ufs-newsletter-popup__input');
  if (input) input.focus();
}
function closeNewsletterPopup(el) {
  el.classList.remove('is-open');
  document.body.style.overflow = '';
  document.activeElement.blur();
}

document.querySelectorAll('.ufs-newsletter-popup').forEach(function (el) {
  var backdrop = el.querySelector('.ufs-newsletter-popup__backdrop');
  var closeBtn = el.querySelector('.ufs-newsletter-popup__close');
  closeBtn.addEventListener('click', function () { closeNewsletterPopup(el); });
  backdrop.addEventListener('click', function () { closeNewsletterPopup(el); });
});
document.addEventListener('keydown', function (e) {
  if (e.key !== 'Escape') return;
  document.querySelectorAll('.ufs-newsletter-popup.is-open').forEach(function (el) { closeNewsletterPopup(el); });
});
Variants

Background

One background only — white (--color-salt) — no colour modifier class exists for this component. Unlike Promo Banner, which ships a --dark modifier for its panel, Newsletter Popup doesn't need one: a lead-capture dialog reads better with a light, neutral panel setting off the photo and the form field's own bordered fill, and there's no second brand context (e.g. an on-image full-bleed treatment) this component needs to support today.

Internationalisation

i18n & RTL

Same split verified behaviour as Promo Banner's own RTL section, now that __image uses the same absolute-positioning recipe: __panel is the row's only in-flow flex item, so its align-items: flex-start auto-mirrors to the visual right under dir="rtl" with no override. Everything else needs an explicit flip, because it's a physical value: text-align: left never flips on its own; __panel's asymmetric padding has its generous --space-20 side hard-coded to right, which has to move to left once __image overlaps that edge instead; __image's own left: 49% and asymmetric radius are physical too — same as Promo Banner's own image; and so is __card's own corner accent. All four are scoped to the same 1024px breakpoint. The close button's inset-inline-end (rather than a physical right) already flips to the visual left automatically. Route every visible string — title, description, placeholder, Continue label, close button's aria-label — through the same data-i18n/data-i18n-ph mechanism as the rest of the header/footer/Announcement Banner.

/* align-items:flex-start on __panel (the row's only in-flow item)
   already auto-mirrors under dir="rtl" — no override needed there.
   Everything below is a physical value that never flips on its own —
   text-align, __panel's asymmetric padding, __card's corner accent
   and __image's absolute left/right + radius — same set of overrides
   Promo Banner's own RTL section documents, scoped to the same
   breakpoint as the rules they override.
   __card uses an attribute selector on itself ([dir="rtl"] as a
   suffix), not a descendant combinator — dir="rtl" sits directly on
   __card in this markup, so a leading [dir="rtl"] .ufs-… selector
   would look for it on an ancestor instead and silently never match. */
@media (min-width: 1024px) {
  .ufs-newsletter-popup__card[dir="rtl"] { border-top-right-radius: var(--radius-xl); border-top-left-radius: var(--radius-xxxl); }
  [dir="rtl"] .ufs-newsletter-popup__panel {
    text-align: right;
    padding: var(--space-16) var(--space-14) var(--space-14) var(--space-20);
  }
  [dir="rtl"] .ufs-newsletter-popup__image {
    left: 0; right: 49%;
    border-radius: var(--radius-xxxl) var(--radius-xl) var(--radius-xl) var(--radius-xl);
  }
}
ℹ️
