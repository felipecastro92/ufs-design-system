Structure

Anatomy & Interaction

A family of content-summary cards sharing one base — image (with an optional badge and favourite toggle), then a body of eyebrow / title / rating / meta, then an optional CTA. Six content types compose the same shared .ufs-tile classes differently, so the differences between them are purely which optional pieces are present, not different CSS. Topic Tile is the one exception: a full-bleed hero/CTA card rather than a content summary, so it doesn't share the base.

Anatomy — shared base

Every tile below (except Topic) is built from these classes. A type either includes or omits __eyebrow, __rating, __meta and __cta — nothing here is type-specific CSS, so none of the 6 cards further down need their own stylesheet beyond this.

One component, context-dependent width and layout — not separate variants: in the flex-carousel, .ufs-tile always renders as the card below, at a fixed width, at every viewport. In a catalog grid it's the same card at a flexible width from 769px up; below 768px, wrapping the grid in .ufs-catalog-grid reflows the same markup into a compact row (image left, content right) — no new HTML, no separate component to choose. Each of the 5 content-summary tiles below shows this reflowed state labeled “Catalog grid — ≤768px”.

Interaction

Hovering the tile lifts it with a shadow + translateY(-2px) — the same treatment already used for product cards elsewhere in this DS, applied consistently across all 6 types (Topic gets a larger shadow only, no lift, since it's already a large full-bleed block). The favourite button toggles independently of the tile's own click-through (event.stopPropagation()), so tapping the heart never also triggers navigation. Try both on any live specimen on this page.

Variants

Tile Types

Eight content types. Six share the vertical .ufs-tile anatomy above — no per-type CSS beyond what's already documented — and each shows both its fixed-width flex-carousel form and its reflowed inline row form (the same markup, restyled by .ufs-catalog-grid below 768px). Brand Tile and Chef Tile don't follow that pattern: both carry their own CSS rather than reusing the shared vertical base — Brand Tile is carousel-only with its own horizontal layout, closer to Topic Tile, while Chef Tile has a fixed/carousel form and a separate --chef-inline modifier for standalone use, rather than the catalog-grid reflow the other six get.

5. Topic Tile

Structurally distinct from the other 5 — no white card, no border, no favourite/badge/rating. A full-bleed background image with a bottom-anchored dark gradient (--color-brand-dark, transparent→solid) carrying an optional eyebrow, title, description and a text link with an arrow. Functions as a hero/category CTA, not a content summary, so it gets its own CSS rather than reusing .ufs-tile's vertical anatomy. Two independent, combinable modifiers: --topic-wide (650px, left/right-anchored instead of centred, larger heading) and --topic-light (colour only — a white-fading gradient with dark text, for topic tiles placed in squid-ink or image-background flex-carousels where the dark default would read too close to the carousel's own dark surface).

8. Chef Tile

Culinary-team profile card: circular avatar, name + role, quote/bio, and a text link through to the chef's full profile. Whole card is a click target, same as Brand/Recipe Tile — a plain <a>, no stretched-link workaround needed since there are no independently-interactive children anymore. Two forms: the default is a fixed 320px carousel card (centred, vertical, with a decorative tinted band behind the avatar); .ufs-tile--chef-inline is a modifier for standalone in-page use — fluid width, capped at a 380px max-width, so it fills a narrow mobile container on its own and caps out on wider ones. Doesn't share .ufs-tile's vertical anatomy, so it carries its own CSS the way .ufs-tile--brand and .ufs-tile--topic do.
