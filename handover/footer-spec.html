Overview

Full Component Preview

The footer is one <footer class="ufs-footer"> made of three stacked zones: a full-width orange newsletter band, a dark main area with the brand column + three link columns, and a bottom bar (copyright + socials) that lives inside the dark area. It's purely presentational — the only script hook is the newsletter form's submit handler.

🧱
Three stacked zones
Newsletter band → dark main (link columns) → bottom bar. The bottom bar is nested inside the dark main, not a separate zone.
🎨
Token-driven, no variants
Single colour treatment (orange band, brand-dark body). Every colour, space and type value resolves from a DS token — no per-instance overrides.
📐
Responsive + localised
Four-column grid collapses to two on mobile; all copy is localised via data-i18n and the layout mirrors under RTL.
ℹ️
Every preview on this page renders the real component CSS (mirrored 1:1 from the source of truth), so hover states on links, the newsletter button and the social icons are live. The newsletter form is presentational here — the nlSubmitFooterEmail() submit handler lives in the full page, not in this spec.

Internationalisation

i18n & RTL

Every piece of copy is localised through data-i18n hooks resolved at runtime by the page's translation layer — the footer itself hardcodes nothing user-facing beyond the English fallback text. Under RTL the whole footer mirrors, with one deliberate exception: the email field stays LTR.

Localisation hooks
Three attribute variants cover the three kinds of text in the footer.
AttributeApplies toExample key(s)
data-i18nPlain text content of the elementfooter-heading, footer-sub, footer-col-company, footer-about … footer-copyright
data-i18n-phThe element's placeholder attributefooter-input-ph
data-i18n-htmlRich text that contains inner markupfooter-tagline (wraps the "by chefs for chefs" span)
HTML
<!-- text nodes localise via data-i18n; placeholders via data-i18n-ph;
     rich text (with inner markup) via data-i18n-html -->
<h2 class="ufs-footer__nl-heading" data-i18n="footer-heading">Stay in the loop</h2>
<input class="ufs-footer__nl-input" dir="ltr"
       placeholder="Enter your email" data-i18n-ph="footer-input-ph" />
<p class="ufs-footer__brand-tagline" data-i18n-html="footer-tagline">Products and services created
  <span class="text-ch-h5" style="display:block">by chefs for chefs</span></p>
⚠️
The email input carries dir="ltr" on purpose: email addresses are always left-to-right, so it stays LTR even when the surrounding document is dir="rtl". Keep this attribute — removing it makes the placeholder and typed address render right-aligned/reversed in Arabic and other RTL locales.
ℹ️
The footer uses logical layout (flex/grid, no hardcoded left/right offsets), so it mirrors automatically under dir="rtl" — link columns flow right-to-left, the newsletter form reverses, and the bottom bar's copyright/socials swap sides. Provide a localised value for every data-i18n key listed above; missing keys fall back to the English text shown in the markup.
