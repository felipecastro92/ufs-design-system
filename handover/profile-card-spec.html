Handover Spec

Profile Card

The titled card every My Account section sits in: a tinted header (icon + uppercase title) over a content body. Two variants: a link card whose header opens its section, and an accordion card that collapses on mobile.

Source
template-profile-*.html
Format·HTML + CSS + JS
Overview

Full Component Preview

.p-card is a white card with a 1px mushroom-500 border and 16px corners. Its tinted header carries an icon and an uppercase overline title. The body holds whatever the section needs: profile details, order cards, forms, lists. The variant decides what the header does. Cards sit in the columns of the Account Tabs & Layout frame, stacked 24px apart.

Structure

Anatomy

Three parts: .p-card (shell) › .p-card-hdr (tinted header: .p-card-title with a 24px icon and label, plus an end affordance, .p-card-arrow or .p-card-chevron) › .p-card-body (16px top / 20px sides and bottom padding, 16px gap between children). A modifier on the shell picks the variant: .p-card--link or .p-card--accordion. The header element follows from it: an <a> for link cards, a <button> for accordion cards.

Variants

Link Card

A summary of a section on another page. The whole header is a single link to that section's tab (My Profile → My profile, My Orders → My Orders, and so on). The arrow slides 5px to the right on hover. The body is a read-only summary. Links inside it, such as order cards, the Reorder button or tiles, are independent and don't trigger the header link. The link card looks the same on every screen size and never collapses.

My Favourites
ℹ️
Used only on Overview today: My Profile, My Orders, My Favourites and Preferences. Every card there is a link card.
Variants

Accordion Card

A section with editable or longer content. On desktop (≥1024px) it's a static card: every body is visible, there's no chevron, and the header isn't interactive. At ≤1023px, where the layout drops to a single column, the cards become an accordion: tapping a header opens that card and closes the others, the chevron flips, and the open card's title turns orange. The first card on the page starts open.

≤1023px, interactive (tap a header)
ℹ️
Used on My profile (Basic information, My Kitchen, Preferences, Delete account) and My Orders (My Past Orders, My Wishlist, Orders & Promos, Chef Rewards). One open card at a time across the whole page, sidebar included, because on mobile the sidebar stacks under the main column into one list.
Behavior

States

Header states per variant. Hover is shown only where the header actually does something: always for link cards, and only at ≤1023px for accordion cards.

Behavior

Accordion Behaviour (JS)

One shared script, called once per page. It only makes accordion cards interactive while the screen is ≤1023px. On desktop, each header button is disabled: it drops out of the tab order, ignores clicks, and loses aria-expanded. So assistive tech never hears about a toggle that does nothing. Crossing the breakpoint (rotating a tablet, resizing) switches modes live. Link cards need no JS.

JS
function initProfileCards(root) {
  var mq = window.matchMedia('(max-width: 1023px)');
  var cards = [].slice.call(root.querySelectorAll('.p-card--accordion'));
  if (!cards.length) return;

  function sync() {
    cards.forEach(function (card) {
      var hdr = card.querySelector('.p-card-hdr');
      hdr.disabled = !mq.matches;                         // desktop: static header
      if (mq.matches) hdr.setAttribute('aria-expanded', card.classList.contains('p-card--open'));
      else hdr.removeAttribute('aria-expanded');
    });
  }

  cards.forEach(function (card) {
    card.querySelector('.p-card-hdr').addEventListener('click', function () {
      var wasOpen = card.classList.contains('p-card--open');
      cards.forEach(function (c) { c.classList.remove('p-card--open'); });  // one open at a time
      if (!wasOpen) card.classList.add('p-card--open');
      sync();
    });
  });

  // First card starts open if the markup didn't pick one
  if (!root.querySelector('.p-card--accordion.p-card--open')) cards[0].classList.add('p-card--open');
  mq.addEventListener('change', sync);
  sync();
}
initProfileCards(document.querySelector('.pg-profile-wrap'));
💡
On desktop the .p-card--open class has no visual effect, since the collapse CSS only applies at ≤1023px. So a card's open/closed choice is kept when the screen grows and restored when it shrinks.

Adoption

Prototype Divergences

The templates were brought in line with this spec on 30 Sep 2026: explicit --link / --accordion modifiers, one 1023px breakpoint, a disabled header on desktop, focus styles, <h2> titles, one shared initProfileCards(), and no extra mobile dividers. The last open item, the card title, is resolved as Orders & Promos.

Internationalisation

RTL

The header is flexbox, so the title and affordance swap sides by themselves. Two small rules are needed: the link arrow image is mirrored, and its hover slide goes the other way. The chevron points down, so it needs nothing.
