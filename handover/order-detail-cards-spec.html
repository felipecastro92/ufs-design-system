Order Summary

Anatomy & Tokens

A bordered card with 16px padding. At the top, the order number (the page's <h1>) with the order status badge beside it, which wraps below on narrow widths. Under that, a list of labelled facts: Order Date, Delivery date, Dispatched by. The label is bold and the value regular, on one line. The order number and status badge are the same classes as the Overview page's "Last order" card.

Order Summary

Reorder Button

A full-width primary button with a cart icon: "Reorder now". It adds every item in the order back to the cart. It's placed in two spots and CSS shows one: on desktop, directly under the summary card in the left column (.pg-order-reorder-desktop); at ≤1023px, after the Order items card at the bottom of the page content (.pg-order-reorder-mobile), so the person reviews the items before reordering.

≥1024px.pg-order-reorder-desktopinside .pg-order-left-col, 16px under the summary card
≤1023px.pg-order-reorder-mobileafter the grid, 16px under the items card, full width
Button.btn.btn-primary · 24px cart icon (white)standard DS button, width 100%
⚠️
Both buttons are in the DOM, and CSS hides one. Keep that in mind for tests and analytics, which should target whichever one is visible.

Responsive

Mobile

At ≤1023px the two columns stack (summary, then items) and the Reorder button moves to the end. At ≤768px the items card tightens its padding and type steps down to 14px (12px for the header). The summary keeps its sizes except the order number (18px). This preview forces those rules at any window width.

Implementation

Accessibility

ℹ️
Recommended markup • Build the lines as a list (<ul> / <li>) so screen readers announce "list, N items".
• Give the product image an alt equal to the product name (as the prototype does), or alt="" if the name is already read next to it.
• Consider linking each product name to its product page, which isn't in the prototype.
• The --completed badge uses margin-bottom: 4px to line up with the heading baseline. A shared badge should align through the header's align-items instead.
Implementation

RTL

No RTL rules needed. Every row is flexbox, so under dir="rtl" the image moves to the right, quantity and price swap sides, and the total aligns to the left (flex-end follows the direction).
