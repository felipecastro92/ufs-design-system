Promo Banner

Campaign/promotion entry point — full-bleed image + content panel, with an optional countdown, logo and secondary CTA. Stacks on mobile, splits into a "nested pill" layout on desktop. Structure, background variants and responsive rules, documented for implementation.

Source
full-page-preview-v0.2.html
Format·HTML + CSS
Overview

Full Component Preview

A single <div class="ufs-promo-banner"> — a full-bleed image (never stretched, always cover) paired with a content panel: an optional logo, a title, an optional description, an optional countdown, a primary CTA, an optional secondary CTA, and an optional disclaimer. Mobile stacks the image over the panel; desktop splits them side by side with the image overlapping the panel's edge (see Desktop & Mobile Layout below).

Structure

Anatomy

Two top-level children of .ufs-promo-banner: __image (a plain background-image div, cover/center, never stretched) and __panel (everything else). Inside the panel: __logo, a __body wrapping __title / __desc / __countdown, then __ctas and __disclaimer as the panel's other direct children.

⚠️
The title uses the h3 type scale (--text-h3-size/-mob-size/-lh) at every breakpoint, not h2, despite the text-h2 class still present in markup — that class now only supplies letter-spacing and font-weight (identical between h2 and h3), since __title's own font-size and line-height declarations override the utility class's values at both breakpoints. Don't remove the text-h2 class; it's still supplying those other properties.
Structure

Desktop & Mobile Layout

Mobile stacks the image above the panel in normal flow. At the 1024px breakpoint, the card becomes a flex row: the panel takes a fixed 52% and the image is pulled out of flow to fill the remainder — not a flush 48/52 split. The image is absolutely positioned 12px past the panel's top and bottom edges and extends slightly past its right edge, so the image's own large top-right radius sits on top of the panel and reveals the mushroom background underneath it — a deliberate "nested pill" seam.

Why the image is position: absolute at desktop
A layout detail worth flagging for anyone extending this component.
Panelflex: 0 0 52%the only in-flow child — its rendered height drives the card's height
Imageposition: absolute; inset: -12px 0 -12px auto; left: 49%tracks the panel's height rather than the other way around; 24px taller than the panel (12px overlap top + bottom)
Image radius--radius-xl --radius-xxxl --radius-xl --radius-xllarge radius only on the top-right corner — the "nested pill" accent
💡
Because the image is out of flow at desktop, the panel's own min-height: 400px is what actually guarantees the card doesn't collapse if the image fails to load or the content is short — don't remove it when customizing panel content.
Variants

Background

One colour modifier, --dark, swaps the card to a squid-ink (--color-brand-dark) background and flips the title/description/countdown text to salt for contrast; the eyebrow-equivalent logo is unaffected by CSS since it's an image, not styled text. The secondary button also switches from its light-surface white-fill treatment to a transparent/salt-outline style.

Default — mushroom-100 background (no modifier)

⚠️
The --dark modifier only recolours text and controls — it doesn't remove the logo, countdown or secondary CTA. The shipped dark instance omits those as a content choice: the ufs-academy-logo.svg asset has a black wordmark that goes invisible on a dark background. If a dark instance needs the logo, use a light/reversed logo asset instead of relying on the modifier to fix contrast automatically.

Internationalisation

i18n & RTL

Flex order already handles most of this for free: the CTA row (flex-direction: row) and the panel-vs-image split both use flexbox, so under dir="rtl" the panel and buttons auto-mirror to the correct side without any override, and align-items: flex-start resolves to the physical right edge on its own. What's left are the properties that are always physical regardless of direction: text-align: left never becomes right on its own, and the image's absolute inset/left/right positioning plus both elements' asymmetric corner radii need an explicit flip — otherwise the image stays pinned to its LTR side while the panel mirrors underneath it, and the two overlap on the same edge instead of meeting in the middle. Live in full-page-preview-v0.2.html: switch the language control to AR to see both instances below translate and mirror in place.

Default — mirrored under dir="rtl"

CSS
/* Flex order + align-items:flex-start already auto-mirror under
   dir="rtl" — verified live, no override needed for those. Only the
   literal-physical values need an explicit flip. Scoped to the same
   1024px breakpoint as the rules they override. */
[dir="rtl"] .ufs-promo-banner__panel {
  text-align: right;
  border-radius: 0 var(--radius-xl) var(--radius-xl) 0;
}
[dir="rtl"] .ufs-promo-banner__image {
  left: 0; right: 49%;
  border-radius: var(--radius-xxxl) var(--radius-xl) var(--radius-xl) var(--radius-xl);
}
ℹ️
These overrides only exist inside the @media (min-width: 1024px) block. Below that breakpoint the panel is already centred (text-align: center) and the image is a normal in-flow block, not absolutely positioned — both are direction-agnostic, so the mobile layout needs no RTL treatment at all.
